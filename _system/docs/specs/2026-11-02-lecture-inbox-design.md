# 강의 수집 도구 (lecture-inbox for Windows) 설계

작성일: 2026-11-02 · 상태: 사용자 검토 대기

## 1. 의도

Study Brain에 넣을 입력을 **한 브라우저 화면에서 모으는** Windows용 로컬 도구다.

사용자는 세종대 학생이다. 지금은 강의 영상 받기, 전사, 파일 정리를 손으로 따로 한다. 이 도구는 그 앞단을 맡는다.

- 이캠퍼스 온라인 강의 영상 받기
- 대면 수업 녹음 파일 받기
- 영상과 녹음을 이 PC에서 전사하기
- 강의자료·족보·과제 PDF를 같이 올리기

결과는 template의 `inbox/`에 과목·학기 정보와 함께 놓는다. 지식화(L1~L5)는 지금처럼 사용자가 Claude Code에서 "넣어줘"라고 할 때 일어난다(방식 1).

참고 원본: https://github.com/EM-H20/lecture-inbox (macOS, React+FastAPI). 작성자에게서 코드를 가져다 써도 된다는 허락을 받았다(사용자 진술). 원본의 세종대 로그인·목록·HLS 다운로드 흐름(`server/school.py`, README "동작 원리" 1~4절)과 Whisper 반복 구간 처리(`server/lecture/repetition.py`)를 이식 대상으로 한다.

## 2. 목표

1. 세종대 이캠퍼스에 로그인해 수강 과목과 강의 목록을 보고, 고른 강의 영상을 받는다.
2. 영상·음성 파일(mp4, m4a, mp3, wav 등)을 끌어다 놓아 전사한다. 대면 수업 녹음이 주 용도다.
3. PDF(강의자료·족보·과제)를 같은 화면에서 올리고 종류를 고른다.
4. 전사는 정확도를 우선한다. 기본 모델은 Whisper `large-v3`이고, 밤새 켜 두는 사용을 전제로 한다.
5. 중간에 꺼져도(창 닫힘, 절전, 재부팅) 다시 켜면 남은 작업부터 이어서 한다. 한 강의 안에서도 이미 끝난 구간은 다시 하지 않는다.
6. 결과물을 template의 L1/L2/L3가 바로 받을 수 있는 형태로 `inbox/`에 놓는다.

## 3. 하지 않는 것 (non-goals)

- 정리 노트 생성과 모의고사. 원본에 있는 기능이지만, 이 역할은 template의 L1·L4·L7이 맡는다.
- 자동 지식화(방식 2). 브라우저가 Claude를 뒤에서 실행하지 않는다. 써 보고 나서 별도 요청으로 다룬다.
- 세종대 외 학교의 다운로드. 다만 다운로드 부분을 분리해 두어, 다른 학교 사용자도 "파일 올려서 전사"는 쓸 수 있게 한다.
- macOS·Linux 지원. 여러 사용자 동시 사용. 화자 분리. 요약.
- PPT·HWP·이미지의 PDF 변환. template 규칙상 PDF만 받으므로, 화면에서 PDF가 아니면 거절하고 변환을 안내한다.

## 4. 실패로 보는 것 (anti-goals)

- 도구가 `raw/`, `study/`, `wiki/`, `_system/log.md`에 쓰는 것. 도구가 쓰는 곳은 `inbox/`뿐이다.
- 학교 비밀번호를 디스크, 로그, 화면, 오류 메시지에 남기는 것.
- 밤새 돌린 전사가 조용히 사라지거나, 실패했는데 화면이 "완료"로 보이는 것.
- 전사에 없는 타임스탬프를 만들거나 원문을 고치는 것. 반복 구간 재디코딩은 허용하지만, 끝내 실패한 구간은 표시만 한다.
- 과목·학기를 도구가 추측해서 적는 것. 사용자가 고르거나 학교 목록에서 온 값만 적는다.
- 몇 GB짜리 영상과 모델이 Obsidian vault나 git에 섞여 들어가는 것.

## 5. 환경과 제약

- 사용자 PC: Windows 11, i5-1135G7(4코어), 메모리 16GB, NVIDIA GPU 없음. 전사는 CPU로 한다.
- 설치돼 있음: Python 3.14(WindowsApps), Node, `uv`, `winget`. 없음: ffmpeg.
- 이 저장소는 코드 저장소가 아니라 학습 지식 저장소다(`CLAUDE.md`). 도구 코드는 노트 영역과 섞이지 않는 곳에 둔다.
- template 규칙(`SECOND-BRAIN.md`):
  - 전사의 표준 입력은 `.md`이고, 자료·기출은 PDF다.
  - 한 입력에 여러 과목이 섞이면 보류된다. 그래서 inbox 묶음은 **과목 하나당 폴더 하나**로 만든다.
  - term 형식은 `YYYY-1`, `YYYY-2`, `YYYY-summer`, `YYYY-winter`다.
  - course-slug와 CRS 생성은 Claude(L1 공통 준비 절차)가 정한다. 도구는 slug를 정하지 않는다.
- 이캠퍼스 연동은 원본 README 기준으로 **실제 계정 검증이 안 된 상태**다. 이 PC에서 사용자 계정으로 직접 확인하는 단계가 필요하다.

## 6. 정해진 것

### 6.1 사용자 흐름 (사용자 확인함)

1. **과목 고르기.**
   - 세종대 로그인을 하면 수강 과목이 뜬다. 학교의 연도·학기를 template term(`2026-2` 등)으로 바꿔 보여 준다.
   - 목록에 없는 과목은 과목명과 term을 직접 입력한다.
2. **넣을 것 고르기** (한 화면)
   - 온라인 강의는 목록에서 체크한다.
   - 녹음·영상 파일은 끌어다 놓고 주차·차시를 적는다.
   - PDF는 끌어다 놓고 종류(자료/족보/과제)를 고른다.
3. **실행.**
   - 다운로드와 전사는 한 번에 하나씩 순서대로 진행한다.
   - 진행률을 화면에 보여 주고, 실패하면 이유를 보여 준다.
4. **결과.** `inbox/` 아래에 과목 묶음 폴더가 생긴다. 화면에는 "Claude Code에서 '넣어줘' 하세요"라고 안내한다.
5. 사용자가 Claude Code에서 "넣어줘"라고 하면 Claude가 묶음을 L1/L2/L3로 처리한다.

### 6.2 inbox 묶음 형식

```
inbox/
└── 20261102-자료구조/              ← <만든 날짜>-<과목명>
    ├── 안내.md                     ← 사용자가 화면에서 지정한 내용
    ├── week_03_01.md               ← 전사 (L1 입력)
    ├── week_03_02.md
    ├── 3주차 강의자료.pdf          ← 원래 파일 이름 유지 (L2 입력)
    └── 2025 중간 족보.pdf          ← (L3 입력)
```

- **전사 `.md`**
  - 한 줄에 한 구간씩 쓴다: `[HH:MM:SS] 문장`. 원본 lecture-inbox와 같은 형식이다.
  - 앞에 머리말이나 frontmatter를 붙이지 않는다. 메타데이터는 `안내.md`에 둔다.
  - 끝내 해결하지 못한 반복 구간은 그 줄에 `[⚠️ 반복 감지 - 확인 필요]`를 붙인다.
- **`안내.md`**
  - 사람이 읽을 수 있는 Markdown이다.
  - 첫머리에 이 파일이 강의 수집 도구가 사용자 지정을 받아 쓴 것임을 밝힌다.
  - 담는 정보:
    - 과목명, term, 학교 과목 코드(목록에서 온 경우만)
    - 파일별 종류(전사/자료/족보/과제)와 주차·차시
    - 전사 출처(이캠퍼스 강의명 또는 원래 파일 이름)
    - 녹음 날짜(파일에서 알 수 있을 때만), 사용한 모델
    - 반복 감지 구간 수
- 같은 날 같은 과목으로 또 만들면 기존 묶음에 추가한다. 이미 있는 파일은 덮어쓰지 않는다.

### 6.3 template 쪽 문서 변경 (작게)

Claude가 `안내.md`를 "사용자 지정"으로 인정하도록 다음을 짧게 적는다.

- `inbox/README.md`에 강의 수집 도구 묶음이 무엇인지 적는다.
- 공통 준비 절차 1·2단계의 "사용자 지정" 근거에 `안내.md`가 포함된다는 한 줄을 넣는다. 위치는 `SECOND-BRAIN.md` 또는 capture 워크플로 문서다.

묶음의 모든 파일을 처리한 뒤 `안내.md`를 어떻게 할지(남김/삭제)도 같은 곳에 정한다. SECOND-BRAIN의 충돌 규칙을 지키고, 새 작업 코드나 레이어를 만들지 않는다.

**과제 원본 보존 (사용자 결정: 일단 이렇게 해 보고, 불편하면 바꾼다)**

지금 L5는 과제 원본이 이미 `raw/<term>/<course-slug>/assignments/`에 있다고 가정한다. `inbox/`의 과제 PDF를 그 위치로 옮기는 단계가 없다. 그래서 L5에 L2 1단계와 같은 방식의 **0단계 "원본 보존"**을 추가한다.

- **`SECOND-BRAIN.md` L5 절**
  - 입력에 "`inbox/`의 과제 원본(PDF)"을 추가한다.
  - 처리 순서 맨 앞에 0단계를 넣는다:
    - 공통 준비 절차로 CRS를 확보한다.
    - 원본을 `raw/<term>/<course-slug>/assignments/`로 옮긴다. 같은 내용이 `raw/`에 이미 있으면 다시 복사하지 않는다.
    - 로그에 `preserve-source`를 남긴다.
    - 이후 단계가 실패해도 이 결과는 유지한다.
  - 완료 조건에 "과제 원본이 그 위치에 있고 ASM의 `source`가 그 경로를 가리킨다"를 추가한다.
- **assignment 스키마:** 선택 필드 `source`를 추가한다(사용자 결정). 원본 PDF가 없는 과제는 `null`이다. 기존 ASM 노트는 고치지 않아도 유효하다. L8의 `source` 경로 검사는 `null`을 누락으로 보지 않는다.
- **`_system/workflows/l5-fact-conflict-reconciliation.md`와 check-conflict 스킬:** 필요한 만큼만 맞춘다.
- **범위 밖:** 공지(`notices/`) 원본의 같은 빈 곳은 이번에 다루지 않는다.

### 6.4 위치

- 코드: `_system/tools/lecture-inbox/`. `_system/hooks/`처럼 시스템 보조 코드를 두는 자리다.
- 크고 PC마다 다른 것은 vault 밖 `%LOCALAPPDATA%\lecture-inbox\`에 둔다. Whisper 모델(약 3GB), 받은 영상, 전사 중 임시 파일, 작업 상태 파일이 여기 들어간다. Python 가상환경도 vault 밖이나 `.gitignore`로 제외되는 곳에 둔다.
- 실행은 저장소 루트에서 명령 하나로 한다. 예: `uv run …` 또는 `_system/tools/lecture-inbox/start.cmd`. 실행하면 브라우저가 열린다.

### 6.5 기술 선택 (내 판단)

- **서버:** Python + FastAPI. `127.0.0.1`에만 바인드한다. 원본 서버가 Python이라 이식할 코드가 그대로 맞는다.
- **화면:** 서버가 직접 내보내는 HTML 한 장 + 순수 JavaScript. React·Vite 빌드는 쓰지 않는다. 화면이 하나뿐이라 빌드 체계가 필요 없고, 나중에 넘겨받는 사람도 Node 없이 쓸 수 있다.
- **전사 엔진:** `faster-whisper` (CTranslate2, CPU `int8`). Windows에서 pip로 설치되고 별도 바이너리가 필요 없다. 원본의 whisper.cpp는 Windows에서 바이너리를 따로 구해야 해서 쓰지 않는다.
- **Python 버전:** `uv`로 3.12 등 휠이 확실한 버전을 고정한다. 시스템의 3.14는 CTranslate2 휠이 없을 수 있다.
- **ffmpeg:** HLS 다운로드와 음성 추출에 필요하다. 첫 실행 때 없으면 `winget install Gyan.FFmpeg` 명령을 안내하고, 사용자 동의 후 실행한다. 몰래 설치하지 않는다.
- **세종대 연동:** 원본 `school.py`의 흐름을 이식한다(표준 라이브러리 `urllib`).
  - 로그인 폼 POST
  - 이캠퍼스 도메인 밖으로의 리다이렉트 차단
  - `logout.php` 링크로 성공 판정
  - 과목·강의 HTML 파싱
  - `viewer.php`에서 m3u8 추출
  - HTTPS와 공인 IP만 허용
  - `ffmpeg -c copy`로 받기, 403이면 Referer를 붙여 재시도
- **보안:**
  - 원본처럼 비밀번호는 로그인 요청에서만 쓰고, 학교 쿠키는 메모리에만 둔다.
  - TLS 검증을 끄지 않는다.
  - 로그와 오류에 학번, 비밀번호, 서명된 URL, ffmpeg stderr를 남기지 않는다.
  - 한 사람이 쓰는 로컬 도구이므로 원본의 다중 사용자 격리·시도 제한·1회용 다운로드 티켓은 필요한 만큼만 남긴다. 받은 영상은 브라우저로 다시 보내지 않고 서버가 바로 전사로 넘긴다.
- **작업 큐와 이어하기:**
  - 작업 상태를 디스크(JSON 등)에 기록한다. 다시 켜면 남은 작업을 이어서 한다.
  - 전사 중에는 끝난 구간을 바로바로 임시 파일에 붙여 쓴다. 다시 켜면 마지막 구간 시각부터 이어서 디코딩한다. 타임스탬프는 원본 영상 기준으로 맞춘다.
  - 전사가 끝나야 `inbox/`에 최종 `.md`를 원자적으로 쓴다.
- **영상 보관:** 전사가 성공하면 받은 영상과 추출한 음성을 지운다. 실패하면 다시 시도할 수 있게 남긴다. 사용자가 올린 원래 파일(예: 폰 녹음)은 지우지 않는다.

### 6.6 모델 비교 단계

구현 중 한 번, 사용자의 실제 강의 5분 분량으로 `large-v3`와 `large-v3-turbo`를 비교한다. 걸린 시간과 전사 결과를 나란히 보여 준다.

Qwen3-ASR은 Windows CPU에서 쉽게 돌아갈 때만 비교에 넣고, 아니면 이유를 보고한다. 결과를 보고 사용자가 기본 모델을 정한다. 모델은 설정 하나로 바꿀 수 있어야 한다.

### 6.7 검토 후 정한 것 (내 판단)

- **온라인 강의의 주차·차시와 수업일**
  - 이캠퍼스 목록에는 강의 제목만 있다. 그래서 강의를 체크하면 주차·차시 칸이 열린다.
  - 제목에 "3주차" 같은 표현이 있으면 그 값을 미리 채워 두지만, 사용자가 확인해야 진행된다.
  - 수업일은 선택 입력이다. 비워 두면 `안내.md`에 "미확인"으로 적는다. LEC `date: null`과 같은 규칙이다.
- **`안내.md`는 도구가 관리하는 파일이다.**
  - 도구는 이 파일을 다시 써도 된다. 항목마다 `완료`/`대기`/`실패`와 실패 이유를 적는다.
  - 파일은 `완료`가 된 뒤에만 묶음 폴더에 나타난다.
  - Claude는 `완료` 항목만 처리하고, `대기`·`실패` 항목은 건너뛰었다고 보고한다.
  - Claude는 `안내.md`를 고치지 않는다.
  - 묶음의 모든 파일이 `raw/`로 옮겨지고 로그에 남으면 Claude가 묶음 폴더를 지운다. 이때 `안내.md`도 함께 지워진다(`inbox/`는 임시 영역).
  - 이 규칙은 6.3의 문서 변경에 함께 적는다.
- **다운로드를 전사보다 먼저 한다.** 학교 로그인이 살아 있을 때 고른 강의를 모두 받고, 그다음 전사를 시작한다.
  - 다운로드 도중 꺼지면 다시 로그인해야 이어진다. 화면에 "다시 로그인하면 남은 N개를 받습니다"라고 안내한다.
  - 전사는 로그인 없이 이어진다.
- **과목 코드**
  - 이캠퍼스 내부 `id`는 학수번호가 아니므로 `code`로 적지 않는다. 대신 `안내.md`에 "이캠퍼스 과목 id"로 따로 적는다.
  - 학수번호·분반은 사용자가 원할 때만 입력한다.
- **절전 방지:** 작업이 남아 있는 동안 PC가 절전에 들어가지 않게 한다(`SetThreadExecutionState`). 작업이 끝나면 해제한다. 화면 꺼짐은 막지 않는다.

## 7. 빌더에게 맡기는 것

- 화면 배치와 모양. 한 화면, 위 흐름 순서만 지키면 된다.
- 파일·모듈 나누기. 다만 세종대 연동은 별도 모듈로 둔다.
- 작업 상태 파일 형식, 이어하기 구현 방식(구간 체크포인트 방식 등).
- 반복 구간 재디코딩의 세부 설정. 원본 방식이 출발점이다.
- 녹음 파일의 주차·차시 기본값 제안 방식. 예: 파일 날짜로 제안하고 사용자가 확인.
- 테스트 범위.
  - 세종대 HTML 파싱, 반복 감지, 이어하기, inbox 묶음 쓰기(덮어쓰기 방지 포함)는 자동 테스트로 확인한다.
  - 실제 학교 로그인과 다운로드는 사용자와 함께 수동으로 확인한다.

## 8. 완료 기준

1. 처음 쓰는 사람이 저장소 루트에서 안내된 명령 하나로 화면을 띄울 수 있다. ffmpeg와 모델 설치는 화면이나 터미널 안내로 해결된다.
2. 사용자 계정으로 이캠퍼스 로그인, 과목 목록, 강의 목록, 영상 받기가 실제로 된다.
3. 폰 녹음 파일 하나가 `large-v3`로 전사돼 `inbox/<묶음>/week_NN_MM.md`에 `[HH:MM:SS]` 형식으로 저장된다.
4. 전사 도중 서버를 끄고 다시 켜면 처음부터 다시 하지 않고 이어서 끝난다.
5. PDF를 올리면 종류와 함께 묶음에 들어가고 `안내.md`에 기록된다.
6. Claude Code에서 "넣어줘"라고 하면 Claude가 `안내.md`의 과목·학기를 근거로 되묻지 않고 L1/L2/L3를 진행한다. 과목이나 학기가 template 기존 기록과 다를 때만 묻는다.
7. 도구 실행 후 `git status`에 `inbox/` 밖의 변경이 없다. 도구 코드 자체의 변경은 제외한다.

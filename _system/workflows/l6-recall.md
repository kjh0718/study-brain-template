# L6 — Recall 실행 문서

대응 레이어: **L6**. 판단 기준의 정본은 [`SECOND-BRAIN.md`](../../SECOND-BRAIN.md)의 `L6 — Recall` 절이다.

> 이 문서는 실행 보조 문서다. 규칙을 새로 만들지 않고 검색 명령, 체크리스트, 보고 형식, 실행 예시만 담는다. 이 문서와 SECOND-BRAIN.md가 다르면 SECOND-BRAIN.md가 맞고 이 문서를 고친다.

## 한눈에 보기

| 항목 | 값 |
|---|---|
| 목적 | 저장된 지식을 근거와 함께 다시 꺼낸다 |
| 입력 | 사용자의 질문 또는 검색 요청 |
| 사전 조건 | 없다 |
| 저장소 쓰기 | **아니오** |
| 호출할 수 있는 레이어 | 없다. 사용자 요청으로만 시작한다 |
| 로그 | **쓰지 않는다** |

**L6은 읽기 전용이다.** 노트를 만들거나 고치지 않고, 로그도 쓰지 않는다. 충돌이나 무결성 위반을 발견해도 답변에만 적는다.

## 0. 시작 전 확인

사전 조건이 없다. 다만 요청이 검색인지 처리 요청인지 구분한다.

| 사용자 요청 | 레이어 |
|---|---|
| "운동량 관련 내용 정리해줘" | L6 |
| "교수님이 마감을 뭐라고 했어?" | L6 (Evidence Recall) |
| "이 전사 넣어줘" | [L1](l1-lecture-ingestion.md) |
| "이 시험 날짜 고쳐줘" | [L5](l5-fact-conflict-reconciliation.md) |
| "중복 개념 정리해줘" | [L8](l8-maintenance.md) / [L9](l9-knowledge-promotion.md) |

검색 요청에 섞여 들어온 수정 요청은 L6에서 처리하지 않는다. 필요하다고 알리고 해당 레이어를 명시적으로 요청받은 뒤에 한다.

## 1. 검색 방법

**검색 순서를 지킨다. 이것이 L6의 핵심이다.**

```text
frontmatter로 후보 좁히기
→ 남은 후보의 본문과 출처만 읽기
→ 필요할 때만 raw/ 확장
```

**1단계 — frontmatter로 좁힌다.** ID, type, title, topics, 관계 필드만 본다.

```bash
rg -n "^(id|type|title|status|course|topics):" study wiki -g "*.md"
```

과목이 정해졌으면 먼저 줄인다.

```bash
rg -ln "^course: CRS-20260908-01" study -g "*.md"
```

topic으로 좁힐 때는 어휘표에서 정확한 slug를 먼저 확인한다(C5). 등록되지 않은 표기로는 찾을 수 없다.

```bash
rg -n "^- " wiki/clusters/_topics.md
rg -ln -A5 "^topics:" study wiki -g "*.md" | xargs rg -ln "momentum"
```

**2단계 — 남은 후보의 본문을 읽는다.** 1단계에서 좁혀진 몇 개만 연다.

**3단계 — 관계를 따라간다.** 개념에서 강의로, 강의에서 자료로 갈 때 쓴다.

```bash
rg -ln "CON-20260415-01" study wiki -g "*.md"
```

**처음부터 전체 본문을 읽지 않는다. 매 질문마다 `raw/` 전체를 읽지 않는다.**

### Evidence Recall — `raw/`로 확장하는 조건

다음 넷 중 하나일 때만 원본을 연다.

1. 정확한 인용이 필요할 때
2. 날짜·수치를 확인할 때
3. 노트끼리 상충해 원문 확인이 필요할 때
4. 사용자가 근거·원문을 명시적으로 요구할 때

이런 요청이 신호다.

- "교수님이 정확히 뭐라고 했어?"
- "이 마감일 근거 어디야?"
- "시험 범위 근거가 뭐야?"
- "원문 확인해줘"

확장 방법은 구조화 노트의 `source`·`sources`를 따라간다. `raw/`를 통째로 grep하지 않는다.

```bash
rg -n "^source:" study/lectures/2026-09-08-physics.md
rg -n "다음 주까지" raw/transcripts/2026-09-08-physics-01.md
```

## 2. 실행 체크리스트

- [ ] **1.** 질문에서 대상 타입, 과목, topic을 좁힌다.
- [ ] **2.** frontmatter로 후보를 좁힌 뒤 남은 후보의 본문과 출처만 읽는다.
- [ ] **3.** 답변을 구성하고 **각 진술에 근거 노트 ID를 붙인다.**
- [ ] **4.** 위 네 조건 중 하나에 해당할 때만 원본을 연다.
- [ ] **5.** 근거를 찾지 못하면 **없다고 답한다.**

## 3. 사용자 확인이 필요한 지점

L6은 쓰기를 하지 않으므로 승인을 받을 일이 없다. 대신 다음을 **알린다.**

| 상황 | 답변에 적을 것 |
|---|---|
| 근거가 부족함 | 추정으로 답하지 않고 무엇이 없는지 적는다 |
| 노트와 원문이 다름 | 충돌을 표시하고 L5 또는 L8 처리를 **제안만** 한다 |
| 노트끼리 상충 | 양쪽을 모두 보여주고 어느 쪽이 유효한지 확정하지 않는다 |
| 관계 필드가 끊어져 있음 | 답변에 적고 L8 검사를 제안한다 |

## 4. 하지 않는 것

- **노트를 수정하거나 새로 만들지 않는다.** 검색 중 오류를 발견해도 고치지 않는다.
- **로그를 쓰지 않는다.** 충돌을 발견해도 `_system/log.md`에 남기지 않고 답변에만 적는다.
- 매 질문마다 `raw/` 전체를 읽지 않는다.
- 근거 없이 답하지 않는다. 그럴듯한 요약을 만들어내지 않는다.
- 노트에 없는 내용을 일반 지식으로 채워 넣고 저장소의 내용처럼 제시하지 않는다. 저장소 밖 지식을 쓸 때는 저장소 근거가 아님을 밝힌다.
- AI 해석을 교수 발언처럼 인용하지 않는다.
- 상충하는 사실 중 한쪽을 임의로 골라 답하지 않는다.
- 과거 기출 빈도를 현재 시험 출제로 답하지 않는다.

## 5. 완료 조건

- [ ] 답변의 각 진술에 근거 ID가 붙어 있다.
- [ ] 확인하지 못한 부분이 표시돼 있다.
- [ ] 저장소를 바꾸지 않았다.

## 6. 답변 형식

L6은 파일을 만들지 않으므로 답변 자체가 결과물이다.

```text
[답변]
운동량 보존은 외력의 합이 0인 계에서 성립한다. (CON-20260415-01)
9월 8일 수업에서 충돌 문제에 적용해 다뤘다. (LEC-20260908-01)
교수님은 이 부분을 중간고사 범위로 언급했다. (LEC-20260908-01, 교수님 강조)

[근거]
- CON-20260415-01 운동량
- LEC-20260908-01 운동량과 충격량 (2026-09-08)
- RES-20260908-01 제3장 슬라이드 pages 21-38

[확인하지 못한 것]
- 시험 범위 확정 공지는 없다. EXM-20260415-01.scope_status: needs-review
- 관련 기출은 PEX-20260909-01 하나뿐이라 출제 경향을 말할 표본이 안 된다

[읽은 범위]
구조화 노트만 읽었다. 원문은 열지 않았다.
```

Evidence Recall이면 마지막 절을 바꾼다.

```text
[원문 근거]
raw/transcripts/2026-09-08-physics-01.md, 00:41:12
> "이 부분은 중간고사에 나옵니다"

[읽은 범위]
LEC-20260908-01의 source를 따라 원문 1건을 열었다.
```

## 7. 로그 기록

**없다.** L6은 로그를 쓰지 않는다.

검색 중 무결성 문제나 충돌을 발견해도 기록하지 않는다. 답변에 적고, 기록이 필요하면 사용자에게 알린다. 기록하려면 사용자가 L5 또는 L8을 명시적으로 요청해야 한다.

## 8. 실행 예시

### 예시 A — 일반 Recall (원문 열지 않음)

> 운동량 관련해서 지금까지 정리된 거 보여줘

1. `topics`에서 `momentum` slug 확인 → 등록돼 있다.
2. frontmatter로 후보를 좁힌다. `CON` 1개, `LEC` 2개, `RES` 1개, `PEX` 1개.
3. 이 5개의 본문만 읽는다. 저장소의 나머지는 열지 않는다.
4. **`raw/`를 열지 않는다.** 인용이나 날짜 확인 요구가 없다.
5. 위 답변 형식으로 근거 ID를 붙여 답한다.

### 예시 B — Evidence Recall (원문 확장)

> 교수님이 과제 마감일을 정확히 뭐라고 했어?

1. `study/assignments/`에서 해당 ASM을 찾는다. `due: null`, `due_status: needs-review`.
2. **구조화 노트만으로 확정하지 않는다.** `due`가 비어 있는 것 자체가 원문 확인이 필요하다는 신호다.
3. `ASM.sources` → `LEC-20260908-01` → `LEC.source` → `raw/transcripts/2026-09-08-physics-01.md`.
4. 그 파일에서 해당 부분을 찾아 **원문 그대로** 인용한다.

```text
[답변]
교수님은 정확한 날짜를 말하지 않았다.

[원문 근거]
raw/transcripts/2026-09-08-physics-01.md, 01:02:15
> "HW3는 다음 주까지 제출하세요"

[확인하지 못한 것]
"다음 주"의 기준이 다음 수업일인지 주말인지 원문에 없다.
ASM-20260908-01.due는 null, due_status는 needs-review로 두었다.
정확한 날짜를 알려주면 L5로 확정할 수 있다.
```

- 원문에 없는 날짜를 만들어 답하지 않는다.
- 이 자리에서 `ASM`을 고치지 않는다. 고치려면 사용자가 L5를 요청해야 한다.

### 예시 C — 노트끼리 상충할 때

> 중간고사 언제야?

`FAC-20260415-03`은 10/15, `FAC-20260908-01`은 10/17인데 `supersedes`가 없고 둘 다 `needs-review`다.

```text
[답변]
확정할 수 없다. 상충하는 근거가 둘 있다.

- 2026-10-15 (FAC-20260415-03, LMS 공지, status: needs-review)
- 2026-10-17 (FAC-20260908-01, LEC-20260908-01 교수 발언, status: needs-review)

supersede 관계가 기록돼 있지 않아 어느 쪽이 유효한지 판단할 근거가 없다.

[제안]
어느 쪽이 맞는지 알려주면 L5로 정리할 수 있다.
정리하지 않은 상태로 두었다. 이 답변으로 저장소를 바꾸지 않았다.
```

- 나중 근거인 10/17을 고르지 않는다.
- 이 자리에서 supersede를 걸지 않는다. 로그도 쓰지 않는다.

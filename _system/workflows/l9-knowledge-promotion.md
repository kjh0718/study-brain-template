# L9 — Knowledge promotion and merge 실행 문서

대응 레이어: **L9**. 판단 기준의 정본은 [`SECOND-BRAIN.md`](../../SECOND-BRAIN.md)의 `L9 — Knowledge promotion and merge` 절이다.

> 이 문서는 실행 보조 문서다. 규칙을 새로 만들지 않고 검색 명령, 체크리스트, 보고·로그 형식, 실행 예시만 담는다. 이 문서와 SECOND-BRAIN.md가 다르면 SECOND-BRAIN.md가 맞고 이 문서를 고친다.

## 한눈에 보기

| 항목 | 값 |
|---|---|
| 목적 | 패턴 승격과 중복 정리 |
| 입력 | 사용자 요청. 또는 [L8](l8-maintenance.md) 검사가 보고한 후보 |
| 저장소 쓰기 | 예 |
| 호출할 수 있는 레이어 | 없다. 사용자 요청으로만 시작한다 |

**L8이 후보를 보고한 것만으로는 실행하지 않는다.** 사용자가 승격 또는 정리를 명시적으로 요청해야 시작한다.

### 두 작업을 먼저 구분한다

**한 번의 실행에서 둘을 섞지 않는다.** 조건이 다르다.

| | 패턴 승격 | 중복 정리 |
|---|---|---|
| 필요한 것 | 서로 **독립적인** 출처에서 반복 확인된 근거 | 두 노트가 같은 대상이라는 **동일성 확인** |
| 결과물 | `wiki/patterns/<slug>.md` | 남길 노트 보강 + 정리할 노트 `archived` |
| 출처가 하나뿐이면 | 승격 불가 | **정리 가능** (같은 전사에서 실수로 두 번 만들어진 노트 등) |

## 0. 시작 전 확인

- [ ] 요청이 패턴 승격인지 중복 정리인지 확정할 수 있다.
- [ ] 사용자가 명시적으로 요청했다. L8 보고서만으로는 시작하지 않는다.
- [ ] 후보 노트의 **전체 본문**을 읽을 준비가 됐다. L9는 다른 레이어와 달리 frontmatter만으로 판단하지 않는다.

## 1. 검색 방법

공통 명령은 [`README.md`](README.md)에 있다.

**중복 후보 찾기** — 표기가 다른 같은 개념을 본다.

```bash
rg -n "^(id|title|status):" wiki/concepts -g "*.md"
rg -n -A5 "^aliases:" wiki/concepts -g "*.md"
```

**두 후보의 근거가 독립적인지 세기** — 승격 조건 1의 핵심이다.

```bash
rg -n -A10 "^sources:" wiki/concepts/momentum.md
```

`sources`에 있는 ID가 몇 개인지가 아니라, **서로 독립적인 출처가 몇 개인지** 센다. 같은 자료를 다시 입력한 것은 하나로 센다. 같은 전사에서 나온 LEC과 그 LEC이 등록한 RES도 완전히 독립적이지 않다.

**근거 노트를 역으로 확인**

```bash
rg -ln "CON-20260415-01" study wiki -g "*.md"
```

**기존 패턴 문서 확인**

```bash
rg -n "^#" wiki/patterns -g "*.md"
```

**정리할 노트를 참조하는 곳 찾기** — 정리 후에도 그 ID는 남으므로 링크를 지우지 않는다. 어디서 참조하는지만 파악한다.

```bash
rg -ln "CON-20260910-02" study wiki -g "*.md"
```

**보호 영역 위치 확인** — C7. 정리 전에 반드시 한다.

읽는 범위는 후보 노트 **전체 본문**, 근거 노트, 기존 `wiki/patterns/` 문서까지다.

## 2. 실행 체크리스트

- [ ] **1. 작업 구분.** 패턴 승격인지 중복 정리인지 정한다. 섞지 않는다.
- [ ] **2. 근거 확인.** 후보의 근거 노트를 모두 읽고 **서로 독립적인 출처인지 센다.**
- [ ] **3a. 패턴 승격이면** 아래 생성 조건 4가지를 **순서대로** 확인한다. 하나라도 미충족이면 문서를 만들지 않고 보류한다.
- [ ] **3b. 중복 정리면** 아래 정리 절차를 따른다.
- [ ] **4. 로그 기록.**

### 패턴 승격 — 생성 조건 4가지

**모두** 충족해야 한다.

| # | 조건 | 확인 방법 |
|---|---|---|
| 1 | 서로 독립적인 근거 노트가 **둘 이상** | 같은 자료의 재입력은 하나로 센다. 이것은 최소 진입 조건일 뿐 타당성 보장이 아니다 |
| 2 | 근거 노트 ID와 **원본 안의 위치**를 적을 수 있다 | 파일 경로만으로는 부족하다 |
| 3 | **반례를 찾아본 범위와 결과**를 적을 수 있다 | 아래 문장 구분을 지킨다 |
| 4 | **적용 범위**를 특정할 수 있다 | 과목, 학기, 시험 유형 등 |

조건 3에서 두 문장을 구분한다.

- 쓸 수 있다 — "확인한 범위에서 반례를 찾지 못했다"
- **쓰지 않는다** — "반례가 존재하지 않는다" (확인할 수 없다)

문서 위치는 `wiki/patterns/<slug>.md`다. 문서에는 패턴 진술, 근거 목록(ID와 위치), 반례를 확인한 범위와 결과, 한계, 적용 범위, 표본 수를 적는다.

`wiki/patterns/`는 Core Type이 아니다. **학습 노트 frontmatter를 강제하지 않고 새 type이나 prefix를 만들지 않는다.**

### 중복 정리 — 절차

현재 스키마에는 "이 노트는 다른 노트로 대체됐다"를 학습 노트 일반에 표현하는 필드가 **없다.** `FAC.supersedes`와 RES의 판 구분은 각 타입 안에서만 정의된다.

따라서 **파일 삭제나 ID 회수를 동반하는 파괴적 병합은 수행하지 않는다.** `redirect`, `merged_into` 같은 필드를 임의로 추가하지 않는다.

- [ ] 1. 두 노트가 **같은 대상인지** 확인한다. 확인되지 않으면 **여기서 멈춘다.**
- [ ] 2. 남길 노트와 정리할 노트를 정한다.
- [ ] 3. **보호 영역은 각자의 원래 파일과 위치에 그대로 둔다.** 옮기거나 재배치하거나 지우지 않는다. 원문 그대로 복사한다는 이유로 이동이 허용되지 않는다. 사용자가 이동을 명시적으로 요청한 경우에만 옮긴다.
- [ ] 4. **보호 영역 밖의** 근거 있는 내용만 남길 노트로 통합한다. 두 노트의 내용이 충돌하면 통합하지 않고 양쪽을 표시한 뒤 사용자 판단을 받는다.
- [ ] 5. 남길 노트에 정리할 노트의 출처가 **모두** 보존됐는지 확인한다. 빠진 것이 있으면 통합을 완료로 보지 않는다.
- [ ] 6. 정리할 노트의 `status`를 그 타입의 `archived`로 바꾸고 본문에 남긴 노트의 ID를 적는다. **파일과 ID는 그대로 둔다.**

그 이상이 필요하면 스키마에 표현 수단을 먼저 추가하도록 제안하고 병합을 보류한다.

## 3. 사용자 확인이 필요한 지점

| 상황 | 처리 |
|---|---|
| 두 노트가 같은 대상인지 확인 불가 | **멈춘다.** 정리하지 않는다 |
| 보호 영역의 내용이 서로 충돌 | 통합하지 않고 양쪽 표시 후 판단 요청 |
| 통합하면 남길 노트에서 기존 출처가 유실됨 | 완료로 보지 않고 보고 |
| 독립 근거가 하나뿐 | 승격 보류 |
| 반례 확인 범위를 적을 수 없음 | 승격 보류 |
| 적용 범위를 특정할 수 없음 | 승격 보류 |
| 파괴적 병합이 필요해 보임 | 스키마 수단 추가를 제안하고 보류 |

## 4. 하지 않는 것

- **파일을 지우거나 ID를 회수하지 않는다.**
- `redirect`, `merged_into` 같은 필드를 임의로 만들지 않는다.
- **보호 영역을 옮기지 않는다.** 병합 대상이어도 원래 파일, 원래 위치에 남긴다.
- 패턴 승격과 중복 정리를 한 실행에서 섞지 않는다.
- 기출 **한 회차**만으로 승격하지 않는다.
- "반례가 존재하지 않는다"라고 쓰지 않는다.
- 근거가 둘이라는 사실만으로 패턴이 타당하다고 쓰지 않는다. 조건 1은 최소 진입 조건이다.
- L8 보고서만 보고 실행하지 않는다.
- 이미 `archived`로 정리한 노트를 다시 정리하지 않는다.
- `wiki/patterns/` 문서에 학습 노트 frontmatter나 새 type·prefix를 만들지 않는다.
- 자동 병합으로 두 노트의 충돌하는 내용을 한쪽으로 덮지 않는다.

## 5. 완료 조건

**패턴 승격**

- [ ] 문서에 근거, 반례를 확인한 범위와 결과, 적용 범위, 표본 수가 **모두** 있다.
- [ ] 근거마다 ID와 원본 안의 위치가 있다.

**중복 정리**

- [ ] 양쪽 노트와 ID가 **모두 남아 있다.**
- [ ] 남길 노트에 출처가 보존됐다.
- [ ] **보호 영역이 원래 자리에 그대로 있다.**
- [ ] 정리할 노트가 그 타입의 `archived`이고 본문에 남긴 노트 ID가 있다.

## 6. 완료 보고 형식

### 패턴 승격

```text
L9 패턴 승격 완료

- 문서: wiki/patterns/momentum-conservation-recurrence.md (신규)
- 작업 구분: 패턴 승격 (중복 정리와 섞지 않음)

생성 조건 확인
  [1] 독립 근거: 3 (PEX-20260909-01, PEX-20260909-02, PEX-20260909-03)
      2022-2 / 2023-2 / 2024-2 별개 회차. 재입력 아님
  [2] 근거 위치: 각 문항 번호와 원본 페이지 기록함
  [3] 반례 확인: study/past-exams/ 전체 5건을 확인했고 그중 2건에는
      해당 유형이 없었다. "반례가 없다"라고 쓰지 않았다
  [4] 적용 범위: 일반물리학2, 중간고사, 교수 동일 여부 미확인

- 표본 수: 3회차 (모두 학생 복원본)
- 한계: provenance가 모두 reconstructed라 원본 시험지로 확인되지 않음
- 이번 시험 출제를 확정하는 서술은 넣지 않았다
- 로그: 1줄
```

### 중복 정리

```text
L9 중복 정리 완료

- 작업 구분: 중복 정리 (패턴 승격과 섞지 않음)
- 동일성 확인: CON-20260415-01(운동량)과 CON-20260910-02(momentum)
  aliases와 정의 본문이 같은 대상을 가리킴. 확인됨

- 남길 노트: CON-20260415-01
- 정리할 노트: CON-20260910-02 → status: archived
  본문에 "CON-20260415-01로 통합됨" 기록

- 통합한 내용: 보호 영역 밖의 정의 보강 1건, 예제 2건
- 출처 보존: CON-20260910-02.sources 2건을 모두 CON-20260415-01.sources에 반영 (확인함)
- 보호 영역: CON-20260910-02의 ## My Understanding 3줄은
  원래 파일, 원래 위치에 그대로 두었다. 옮기지 않았다
- 파일·ID: 둘 다 그대로 남아 있다. 삭제하지 않았다
- 참조 정리: CON-20260910-02를 참조하는 노트 3건은 그대로 두었다
  (ID가 살아 있으므로 끊어진 링크가 아니다)

- 보류: 없음
- 로그: 2줄
```

## 8. 실행 예시

### 예시 A — 승격하지 않는 경우

`PEX-20260909-01` 한 회차에서 운동량 문항이 3개 나왔다.

- 조건 1: 근거 노트가 **1개**다. 한 회차 안의 문항 3개는 독립적인 출처가 아니다.
- **문서를 만들지 않는다.** 로그에 `held`로 남기고 보고한다.

```text
승격하지 않았다.
독립 근거가 PEX-20260909-01 하나뿐이다. 한 회차 안의 문항 3개는
서로 독립적인 출처가 아니므로 조건 1을 충족하지 않는다.
다른 회차 기출이 들어오면 다시 판단할 수 있다.
```

기출 한 회차만으로 승격하지 않는다.

### 예시 B — 보호 영역이 있는 중복 정리

`CON-20260415-01`과 `CON-20260910-02`가 같은 개념이고, 뒤쪽에 사용자가 쓴 내용이 있다.

```markdown
<!-- CON-20260910-02 -->
## My Understanding

충격량을 "힘 × 시간"으로 외웠는데 적분이 더 정확한 표현인 듯.
아직 헷갈림.
```

**하는 것**

- `## 정의`, `## 예제` 등 보호 영역 **밖의** 내용만 `CON-20260415-01`로 통합한다.
- `CON-20260910-02.sources`의 근거 ID를 남길 노트에 모두 반영한다.
- `CON-20260910-02.status`를 `archived`로 바꾸고 본문에 적는다.

  ```markdown
  이 노트는 CON-20260415-01로 통합되었다. 파일과 ID는 기록으로 남긴다.
  ```

**하지 않는 것**

- `## My Understanding`의 세 줄을 `CON-20260415-01`로 **옮기지 않는다.**
- 그 세 줄을 요약하거나 두 노트의 사용자 메모를 합치지 않는다.
- `CON-20260910-02` 파일을 지우지 않는다.
- `CON-20260910-02`를 참조하던 노트의 링크를 지우지 않는다. ID가 살아 있다.

원문 그대로 복사한다는 이유로도 보호 영역 이동은 허용되지 않는다. 사용자가 명시적으로 옮겨 달라고 할 때만 옮긴다.

### 예시 C — 멈춰야 하는 경우

`CON-20260415-01`(운동량)과 `CON-20260910-03`(각운동량)이 중복 후보로 보고됐다.

- 이름이 비슷하지만 다른 개념이다. **같은 대상인지 확인되지 않았다.**
- 절차 1단계에서 멈춘다. 통합하지 않고 `status`도 바꾸지 않는다.

```text
정리하지 않았다.
CON-20260415-01(운동량)과 CON-20260910-03(각운동량)이 같은 대상이라고
확인할 수 없다. 정의와 적용 조건이 다르다.
동일성이 확인되지 않으면 정리하지 않는다는 규칙에 따라 멈췄다.
```
